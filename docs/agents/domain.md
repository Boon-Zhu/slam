# 领域文档

工程 skill 探索本仓库代码库时，按以下规则使用领域文档。

## 探索前读取

- 仓库根目录的 `GLOSSARY.md`。
- `docs/adr/` 中涉及待修改领域的 ADR。

如果这些位置尚不存在，直接继续工作即可。不要仅因文档缺失而停止，也不要预先创建占位文件。只有在术语或架构决策真正确定后，领域建模流程才按需创建这些文档。

## 文件结构

本仓库采用单上下文布局：

```text
/
├── GLOSSARY.md
├── docs/
│   ├── adr/
│   └── agents/
└── ...
```

## 使用词汇表中的术语

在 issue、ticket、重构建议、假设或测试中命名领域概念时，使用 `GLOSSARY.md` 已确定的术语。不要引入词汇表明确排除的同义词。

如果所需概念不在词汇表中，先判断应复用已有项目语言，还是确实存在需要领域建模解决的术语空缺。

## 标出 ADR 冲突

如果建议与已有 ADR 冲突，明确说明冲突，不得静默覆盖既有决策：

> 与 ADR-0007（示例决策）冲突，但值得重新讨论，因为……

## README 仍是架构入口

对于本 DOGZILLA S2 仓库，`README.md` 仍是需求与顶层架构共识的入口。领域文档用于补充它，不能替代其中已确认的决策、候选组件或尚未完成的真机核实项。
