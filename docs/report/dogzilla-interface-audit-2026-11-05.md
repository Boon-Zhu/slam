## 2. MS200 的 LaserScan 接口

### 2.1 启动参数与串口

L 第 21–40 行实际启用的节点为 package `oradar_lidar`、executable `oradar_scan`、节点名 `MS200`。第 5–19 行三引号内是示例注释，不能将其中 `MS200/scan` 和带尾空格的串口字符串当作实际配置。

| 参数 | L 实际传入值 | 含义边界 |
| --- | --- | --- |
| `port_name` / `baudrate` | `/dev/ttyAMA1` / `230400` | 与狗控制串口 `/dev/ttyAMA0` 不同 |
| `device_model` | `MS200` | S 第 205、257 行实例化模型常量 `ORADAR_MS200`；字符串参数主要用于日志 |
| `scan_topic` / `frame_id` | `/scan` / `laser_frame` | 话题绝对名，frame 不带 `/` |
| `angle_min` / `angle_max` | `0.0` / `360.0` | 输入过滤角，单位为度；不是直接赋给 LaserScan 的角度上下界 |
| `range_min` / `range_max` | `0.05` / `20.0` | 输出距离限制，单位米 |
| `clockwise` | `False` | S 第 145–151 行使用 `360 - 原始角度` 重排 |
| `motor_speed` | `10` | D 第 277 行速度反馈转换注明 Hz；目标值不等于实测发布频率 |

S 第 307–313 行在开始扫描前比较当前转速与目标 ±10%，超出时调用设速；D 的 `SetRotationSpeed()` 第 526–536 行将设定值限制到 5–15。启动驱动可能设置雷达转速，不能称为完全不向硬件写入的读取。

### 2.2 时间戳与组帧

**源码事实：** S 第 321–345 行先取 `node->now()` 为 `start_scan_time`，再调用 `GrabFullScanBlocking(scan_data, 1000)`，然后再次取主机时间。传给发布函数的 `scan_duration` 是这次调用前后时间之差。S 第 115、121–122 行分别将前者写入 header stamp，将后者写入 `scan_time`，并以 `scan_time / N` 写入 `time_increment`。

D 第 274–280 行在 CRC 正确时读取包的硬件 timestamp 和转速；第 296–318 行根据角度跨圈累计整帧，起始角大于 10 度的帧不置 ready。D 第 714–734 行 `GrabFullScanBlocking()` 等待事件、复制已就绪缓存；S 的 ROS 发布路径没有调用 `GetTimestamp()`。

**由源码推导的限制：** header 时间是主机开始等待的时间，不是已证实的第一束激光采样时间；等待时长也不一定等于完整物理扫描周期。缓存已有数据、调度延迟、超时和角度重排均需要实测评估。不能仅据 `time_increment` 字段存在便宣称运动去畸变时序可靠。1000 ms 是单次等待超时参数，不是项目的雷达失效判定时限。S 第 338–348 行仅在成功时发布，失败时没有发布专门的故障消息。

### 2.3 角度、无效值和强度

S 的 ROS2 `publish_msg()` 第 108–188 行给出的算法如下：

- `N = vailtidy_point_num`，`angle_min/max` 取原始首末点角度并转换为弧度，`angle_increment = (末角 - 首角) / N`。因此一般不满足“末角 = 首角 + (N-1) × 增量”的端点关系；这是源码可见的数值关系，实际影响须结合样本判断。
- 距离乘 `0.001` 写入米制数值。`ranges`、`intensities` 初始全部为 NaN。
- 超过最大距离、低于最小距离或落在输入角度窗口之外的点被设成距离 `0`、强度 `0`，并非统一转成 `+Inf` 或 NaN。
- 转向处理之后按角度计算无符号整数桶索引，只写入 `index < N` 的桶。空桶可能继续为 NaN。
- 多点落同桶时保留更小距离；无效 `0` 也参加这个比较，可能压过该桶有效距离。强度仍写本次点的强度，因此强度不一定对应最终保留的最小距离。
- 若本次空桶索引比上次索引大 2，额外把本次距离、强度复制到中间桶。这是填值逻辑，不能将每个非 NaN 桶都解释为独立激光测量。

以上均来自 S 第 113–184 行。静态检查本身没有统计实机 NaN/零值占比；§2.5补充了一帧计数，但没有验证盲区、近距离漏检、反光干扰或扫描角度方向；障碍检查不能直接把零值或缺失桶当成“无障碍”。

### 2.4 QoS

S 第 254 行是 `create_publisher<sensor_msgs::msg::LaserScan>(scan_topic, 10)`；代码没有显式采用 `SensorDataQoS` 或设置 best effort。源码直接证明的是深度参数 10 和未显式覆盖其余策略。按 ROS2 Humble 常规整数深度重载，预期为 keep-last 10、reliable、volatile；静态检查未在这一源码副本中核对 rclcpp 头文件实现；随后运行端点查询确认了 reliable/volatile，详见下一节，未确认depth。不能把“传感器话题”自动等同于 best effort。消费者应以实际端点信息核对兼容性。

## 3. DOGZILLALib 反馈协议与返回值

### 3.1 通信基本约束

P 第 122–132 行构造即打开 `/dev/ttyAMA0`，115200 baud，serial timeout 0.5 s，并清空输入输出缓冲；它不是无副作用的能力探测对象。`__read()`（第 150–160 行）清空缓存、发出读请求；各 read 方法紧接着调用 `ser.read_all()` 丢弃当时已有字节，再进入解包。由此存在快响应被提前读走的潜在时序问题，尚未通过真机重现。

`__unpack(timeout=1)`（第 600–675 行）以墙钟循环检查串口，验证头尾和校验和，超时返回 False；接收的类型、地址被记录，但没有与本次请求的地址/预期长度进行匹配验证，也没有公开样本时间、序号或质量标志。固定 50 字节缓冲并未给不合理报文长度做显式上界校验。多个实例同时读取同一串口会争抢字节；库中没有跨进程所有权协调。

下表中的“失败返回”指正常进入解包且解包超时/失败的路径；串口打开/读写异常、解码错误等并不保证被转成该返回值。

| 方法与来源 P | 成功返回 | 解包失败返回 | 单位与限制 |
| --- | --- | --- | --- |
| `read_motor()`，485–505 | 12 个角度组成的 list；默认保留两位小数，`out_int` 可取整数 | `[]` | 按 52、97–103 行区间映射；每三项范围依次 `[-73,57]`、`[-66,93]`、`[-31,31]`；J 第 66–69 行把它按度转换为 rad，因此“度”有消费方证据；反馈是否编码器实际位置仍待底层确认 |
| `read_battery()`，507–514 | 收到的第一个字节转整数 | `0` | 没有电压/电流换算；代码本身不足以证明校准过的百分比；0 同时可能是有效返回与失败占位 |
| `read_version()`，516–525 | 10 字节应答中 `[2:10]` UTF-8 解码并去除尾部 NUL | 字符串 `Null` | 非完整10字节原文；解码异常未捕获 |
| `read_roll/pitch/yaw()`，527–561 | 4 字节小端浮点，默认 round 到两位；`out_int` 截断整数 | 数值 `0` | 方法本身不转换单位；结合同协议原始角度转换推测为度，尚缺硬件角度对照；不能与raw接口直接混用 |
| `read_imu_raw()`，564–598 | `[accX,accY,accZ,gyroX,gyroY,gyroZ,roll,pitch,yaw]` | 九个 `0.0` | 以下详述；无valid标志与采样时间 |

`Byte2Float()` 第 106–112 行先反转 4 字节再以网络序 float 解码，即按小端 float 输入处理。`read_imu_raw()` 请求地址 `0x65`、长度 24；前三轴按小端有符号 int16 `/16384 * 9.8`，后三轴 int16 `/16.4`，最后三个 float `/180 * 3.14`。

**单位证据边界：** 加速度表达式明显按重力加速度换算为 m/s²；欧拉角表达式将度转换成近似 rad。陀螺仪 `/16.4` 本身没有单位注释或传感器量程依据，按常见灵敏度解释很可能为 °/s，但这里只能列为待核实假设，不能当成已确认 rad/s。需要固件/传感器规格或已知角速度实验闭环确认。轴向、正负号、重力是否保留、姿态融合算法、yaw参考和漂移均未从这些函数得到验证。

P `stop()` 第 162–166 行顺序发送 x=0、y=0、mark_time=0、turn=0；没有停止确认、物理速度回读或制动距离计算。`move_x/move_y/turn` 使用的 25、18、100 是命令映射上限，不是经校准的 SI 实际速度（P 第 48–57、176–201 行）。

## 4. 现有 ROS 包的接入风险

### 4.1 yahboom_base 运动入口

B 第 8–18 行节点 `cmd_vel_sub` 订阅相对话题 `cmd_vel`，Twist，队列深度 1，自己构造一个 DOGZILLA 串口实例。第 20–42 行取 linear.x/y、angular.z；三轴绝对值均小于 0.05 才调用 stop，否则将各轴限制至 ±100，再统一乘 40 发送给库。库还有自身饱和映射，所以这个倍率不能证明 Twist 的 m/s、rad/s 到实际机身速度正确。

B 全文没有命令超时定时器、来源仲裁、障碍检查、保护状态、里程计发布或结束时 stop。正常退出执行 destroy/shutdown（44–55），也不等于物理停止。这里只证明此节点没有这些机制，不能据此断言底层固件一定没有 watchdog；固件行为仍待验证。该节点直接订阅 cmd_vel，若用于项目，启动和连接关系必须服从 D→C→A 的已定运动通路。

### 4.2 yahboom_dog_joint_state 联合关节/IMU发布

J 第 37–47 行独立打开 DOGZILLA，发布 `/joint_states`（深度5）与相对话题 `imu/data_raw_self`（深度10），IMU frame 为 `imu_link`。定时器设为 0.05 s，但不能据此宣称 20 Hz 实际反馈。

| 已核实源码行为 | 对消费方的影响与验证边界 |
| --- | --- |
| 读关节前给 JointState 打主机时间；随后串口读，再固定 sleep 0.1 s，再读IMU（57–64、96–99） | 发布频率受睡眠和串口超时约束；关节与IMU不是同时采样；尚未测实际频率/延迟 |
| position 对索引1、4、6、9取负号（66–69），velocity却对所有原角度直接差分除0.05（77–89） | 对上述关节，位置与速度的符号定义不一致；真实回调间隔也不等于固定0.05，差分速度不可直接信任 |
| IMU仅当`imu_raw[0] != 0`更新缓存；之后无条件读取last_imu（98–102） | 有效的零X加速度会被当成无更新；首次无有效缓存可能IndexError；后续失败可能继续复用旧值 |
| 复用缓存时仍重新设置IMU header时间（111）并发布（128） | 新鲜时间戳不能证明新鲜样本；需独立有效性/样本年龄语义 |
| gyro原值直接填angular_velocity（115–117） | 若库值为°/s，则不符合ROS Imu的rad/s要求；单位尚待固件/实测核实，不能直接融合 |
| 未设置任何covariance（40、108–129） | 保持消息默认值；不是已经估计噪声、方差或通过滤波标定的证据 |
| 仅捕获IndexError并输出“获取舵机状态失败”（130–132） | IMU缓存索引错误也显示同一提示；无有效状态话题；串口异常不是这条捕获路径 |

J 第 59 行的 `lf_lower_leg_link` 看似不是 joint 名，但 U 第 202–204 行确实把该 revolute joint 也命名为 `lf_lower_leg_link`。所以不能只凭后缀将其报告成确定的joint名称不匹配；应对实际加载的整份URDF逐项核对。这里保留上游命名，不提出重命名修改。

B 与 J 若同时按默认方式启动，会分别打开同一 `/dev/ttyAMA0`；P 的每次读取还会清空输入缓冲。由源码可确定缺少协调机制，是否发生串扰须在有明确串口所有者的受控方案中验证，不能直接把两个节点并跑作为无风险的发现步骤。

### 4.3 TF 的候选冲突

- L 第 43–56 行额外启动静态TF `base_link → laser_frame`，平移 `(0,0,0.18)`，旋转零。它是写死的装配假设，未证明原装实机测量一致。
- T 第 13–32 行使用动态 TransformBroadcaster 每0.1 s发布固定的 `base_footprint → base_link`，平移 `(0.1154,0,0.047)`，单位四元数。代码注释“IMU和雷达之间”与实际frame不一致，应以字段为准。
- U 第 7–12 行同时定义固定 `base_footprint → base_link`，但平移是 `(0,0,0.010)`。若这份模型通过robot_state_publisher发布且T同时运行，会构成相同TF边的不同发布者和不同数值。这里是条件式冲突，未观测到实时重复发布。
- U 第 850–859 行定义 `base_link → imu_link`，平移 `(0.085,0.000044164,0.070)`、零旋转；与L的雷达TF并不是同一坐标系，不能仅按frame名字假定轴向和安装位置正确。

上述B/J/T没有可证实实际底盘位移的odom数据来源。本文不把关节角、命令积分、IMU欧拉角或雷达驱动的存在当作B模块里程计质量验收，也不对工作区其他候选里程计包作不存在断言。
