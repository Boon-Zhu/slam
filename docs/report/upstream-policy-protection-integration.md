# 未修改上游策略评估：C 保护与 D 集成

日期：2026-11-02。范围：快速验证版的 C/D；静态源码和官方文档研究，未构建、回放、连接机器人或执行停车测试。人时为拆项判断，不是测量或承诺。

## 结论与策略粒度

用户已明确：允许未修改的上游库与组件，确需修改时重写**最小独立节点或组件**。据此，C/D 可以采用“原样依赖 + 自有业务节点 + 自有 launch/config”，通常不必修改 Nav2，也不必重写整个 collision_monitor。项目的授权、故障确认、踏步与停止区别，本来就是项目业务缺口；不能把全部自研成本都算成这一策略新增成本。

主要收益是消除私有补丁、合并冲突及补丁回归的维护面，代码归属和入口更清楚；这不等于不检查上游接口，也不等于减少总验证工作。替换小节点有时比层层适配清楚，替换复杂保护算法则会把原本的集成验证扩大为算法实现与集成两项验证。

## 当前需求基线

以[阶段决议 §7.2–§7.18](../architecture/interface-baseline-decisions.md)为准：

- A 集中检测并报告设备/数据错误，C 按报告响应。本轮未采纳 C 再独立判断传感数据过期和 TF 故障的实现要求；旧 `.scratch/vendor-reuse/protection-integration.md` 中的此类建议不能直接作为本版工作量。
- 雷达故障先停止平移/转向，在原持续操作下保持踏步；等待 D 展示故障并接收确认。确认不构成运动指令，C 确认生效后须重新操作才允许人工降级平移/转向，明确显示避障未生效；松开仍停止踏步，通信故障仍停止。
- 用户入口是 D，运动只走 D→C→A；A 负责收到 C 有效命令的超时兜底。A 无报告失联如何检测仍未决，不得因采用未修改上游而声称这项已解决。
- 快速版必须完成采集、建图与保存反馈；独立定位、绑定启动位姿及模式切换延期。D 不在本轮重写地图保存内部逻辑；B 提供实际保存结果。

## 三种实现边界的代价

| 方案 | 自有内容与未改上游 | 检查边界与实际代价 |
| --- | --- | --- |
| 外部编排/适配，优先验证 | D 操作入口、C 授权和确认状态、运动状态表达、launch/config；障碍几何候选用原样 collision_monitor | 不维护上游补丁；仍检查数据/命令契约、参数、恢复行为及实际停车。要证明上游输出能满足方向保护，不能从“可启动”推断满足。 |
| 替换最小节点/组件，符合用户策略 | 原厂自主避障节点不适合人工过滤时，另写有明确输入输出的有限方向过滤器；仍使用 ROS2/TF 等原样库 | 可以删除不需要的自主运动和多传感器分支，缩小需理解的代码面；同时新增几何、方向、转身扫掠、无效值与状态组合验证。只支持当前范围不代表复刻 Nav2 功能。 |
| 重写整个 collision_monitor，非本轮建议 | 承担多个数据源、几何模型、TF、生命周期、参数和消息处理 | 比用户要求的最小组件更大；即使代码更易读，也不能借此继承上游测试结论或成熟度。若项目只需要小子集，应明确这是窄功能替代，不称为等价重写。 |

方向退开、踏步与降级状态可能决定是否采用小过滤器：不要为了保留 collision_monitor 而添加复杂输出旁路。也不能把“禁改上游”理解为先决定重写，再寻找需求。先用真实接口和少量代表用例判断候选能否配置满足；确有缺口再确定最小替换边界。

故障确认、旧命令作废、松开停止等可作为外部业务逻辑；APPROACH/STOP 的几何行为本身不匹配时，外部包装不一定足以正确修复。运行中依据状态选择正常过滤或已确认降级路径，最终执行权仍留在 C，不能通过 D 直接发 A 绕过确认。

## 粗略人时与约 80 人时预算

假设团队无 ROS 经验、有 agent 辅助，A 能按约交付运动/错误接口及录包，B 能提供建图/保存结果；使用最小交互入口，不开发完整 GUI。以下包括读接口、实现、人工审查、代表性输入/回放检查和修复，不是代码生成时间。区间反映经验不足和实机接口未知，没有采用统计置信度。

| 工作 | 原本必做估计 | 禁止修改上游的直接新增 |
| --- | --- | --- |
| C：持续操作、确认/降级、恢复、正常障碍限制、原因输出及代表性检查 | 14–24 人时 | 接口原样可用时约 0–3 人时的边界/依赖记录；若必须以小组件替代已有算法，另加约 6–14 人时，取决于范围 |
| D：最小操作入口、launch/参数、保存结果展示、全局状态、最小 CI 成功/失败试运行 | 10–18 人时 | 约 0–3 人时，主要为依赖清单、外部启动组合整理 |
| C/D 端到端集成与典型故障操作记录 | 6–10 人时 | 正常不新增整轮；替换组件触发的重查已计上述替换增量 |
| C/D 合计（原样依赖可用路径） | **30–52 人时** | **0–6 人时** |

这里集成项只计 C/D 人员花费；A 的停止接口、硬件检查，B 的建图/保存内部开发及他们参与联调的时间不在此表，汇总时按实际参与人分别计时，不重复套一笔“全团队集成”。不把同一份 CI 搭建再计入 A/B。

“小组件替代”也不必全是策略成本：若上游本来无法满足需求，即使允许 fork 也要实现和验证缺口。表内 6–14 人时是相对于“原样候选已满足”路径的条件增量，不能直接解释成相对于一个尚未估算的补丁方案的净损失。重写整个 collision_monitor 的项目所需子集，粗估再增加约 24–48 人时；若声称多源/多动作等功能等价，不能据此区间承诺完成。

因此 C/D 已会占总 80 人时较大部分，余量必须留给 A/B、学习及设备阻塞；不能承诺两周必达。agent 可以加快脚手架和用例生成，但真实单位、踏步/停止接口、遮挡和实际运动响应仍需团队验证。重写复杂核心最容易挤掉这些必要工作。

## 最小验证与维护边界

快速版先核对：持续按住/松开、正常障碍阻挡及解除、A 报雷达故障后等待确认、确认本身不动、重新操作降级、通信故障不被确认解除、地图保存失败反馈、C 消失后 A 的超时反应。回放能检查感知与消息行为，真实步态、停止及扫掠只能现场检查；不将复杂项穷尽测试作为快速版完成门槛，未验证项记录延期。代表用例顺序需与 A/C/D 的真实接口共同确认。

维护上建议每个原样依赖记录来源/版本，参数和启动组合进入项目审查；小替代组件拥有明确行为范围及项目测试。策略减少的是“自研逻辑和修改上游混在一起”的追踪成本，不会自动消除对上游版本、接口、实际输出的检查。以上是研究建议，不修改现有选型或验收决议。
