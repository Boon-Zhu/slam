- 镜像 `yahboomtechnology/ros-humble:3.8` ID 仍为 `sha256:7e79c61b64b81311caf297640e5c6fd70279be4cbd38c2c087e8e3395e566047`。
- 宿主 Python 3.11 和容器 Python 3.10 的实际 DOGZILLALib 3.1.9 实现源码 SHA-256 相同：`3d05141c71b1066e2274cb0d842bd45b328c6d57a9032b7484494433b185585d`。不是仅凭包版本名推定一致。

- 临时容器均使用只读根文件系统、隔离网络、丢弃 capabilities，按探查分别只映射 UART0 或 UART1，不启动整机 launch；退出后删除。最终无容器、两个 UART 无持有者。

## 3. MCU 反馈：原始帧比库返回值更完整

宿主进行 3 轮、每轮 7 项查询，逐条保留单调时钟、未同步系统时钟、请求字节、接收字节及库返回值。独立复核 21 帧的帧头、长度、地址、校验和及帧尾均正确；没有把失败占位零当成成功。探查包装器仅观察串口读写，限制发送内容为厂商读取帧；未修改厂商实现、未调用运动或配置方法。

容器内也进行反馈复查。第一次容器探查的终端输出发生截断，因此另做一轮完整的 7 项查询并保存到 `container-feedback.jsonl`；这轮 7 帧均通过同样的结构校验。被截断的输出保留为不完整日志，不纳入完整留证统计。

| 查询 | 本轮结果与解释 |
| --- | --- |
| `read_battery()` | 宿主 35、35、34；后续完整容器查询为 32。按 OLED 源码为百分比，不是伏特或精确剩余续航；不能据此证明此前趴地原因。Pi 的 `throttled=0x0` 也不能替代机器狗电池诊断。 |
| `read_version()` | 原始载荷是 `M-4.0.1-Y\0`；库截去前两字节后返回 `4.0.1-Y`。说明书应保留二者，避免丢失型号前缀信息。 |
| `read_motor()` | 宿主首轮返回 `[10.1,43.12,0.85,9.59,43.74,0.85,10.61,53.72,0.85,10.61,54.96,0.61]`。实际响应载荷有 **15 字节**，库只转换前 12 字节；尾部 `00 ff 00` 的含义未知，需原样保留，不能擅自解释为其他关节。 |
| `read_roll/pitch/yaw()` | 宿主分别约 −0.11～−0.13、0.09～0.13、−0.60；有效帧可读，不代表角度零点/坐标系已标定。 |
| `read_imu_raw()` | 宿主三帧的加速度 z 返回值约 −9.698、−9.758、−9.741；其他分量也变化。24 字节载荷包含库解释的三轴加速度、三轴角速度、roll/pitch/yaw。不是全零占位；静止重力方向的物理解释仍需现场姿态参照。 |

库名称中的 `raw` 不表示完全未处理：源码对前三项使用 `/16384*9.8`，角速度使用 `/16.4`，姿态使用 `/180*3.14`。单位需据协议/制造商及实测核实，尤其不能将角速度返回值未经确认就写入要求 rad/s 的 ROS Imu 字段。保留字节和转换值，派生标准单位数据另记来源。

响应载荷未提供采样时间戳；本轮记录的是请求/接收过程时间。`read_all()` 会丢弃其读到的内容，本轮记录到的该部分均为空，但不能据此断言长期运行不会丢数据。成功读取仅数毫秒，而源码 `__unpack()` 默认用 `time.time()` 等待约 1 秒；本轮没有注入超时，没有验证其最坏时延或计时受校时影响时的行为。

目前“设备确实返回 IMU 类数据”已有实机证据；传感器芯片型号、安装轴向、精度与动态有效性仍不能单凭接口返回推定。关节值也未通过人工改变关节等对照试验证明为独立实测反馈而非内部目标/估计值。

## 4. 相机复查

初始相机枚举支持 MJPG 和 YUYV，多种尺寸/帧率；查询到的原状态为 MJPG 640×480、120.101 fps。这个数字是驱动配置声明，不是实际持续出帧率。

第一次 OpenCV 读取获得 30 帧，但像素均值仅约 0.01–0.19（8 位图像），几乎全黑。用户确认保护盖未取下并处理后，第二次读取获得 60 帧，640×480×3；首末接收时刻计算约 29.81 Hz，末帧均值约 27.80。已在电脑查看样图，能够辨认室内地面、椅子和柜体；画面仍偏暗，不能据此声明成像质量或标定通过。

检查使用 OpenCV V4L2，实际协商为 YUYV 640×480 / 30 fps；每帧输出 BGR 为 921,600 字节。若按 30 Hz 原样保存 BGR，仅像素约 27.65 MB/s，约 1.66 GB/min，这是算术预算，**不是实测写盘吞吐**。正式采集格式与容量不能直接沿用单张 JPEG 大小推算所有场景。

仅末帧另存 JPEG 作为调查样图，不是原始相机流或正式数据片段。机器人保留 `/tmp/dogzilla-camera-check-2026-11-08.jpg`，电脑保存于本地证据目录；两端 SHA-256 均为 `fbf5177d4c54f57d4be47aae0c0acdadfe1b92ab50501a9ffa685f43481928ba`，文件 65,710 bytes。探查结束后通过 V4L2 将格式/帧率恢复为初始的 MJPG 640×480 / 120.101 fps，并复查成功；未重启 APP。

## 5. 雷达、TF 与已有里程计

单独运行 `oradar_scan`，沿用 MS200 参数，只有 UART1 映射；没有启动附带 TF 或控制节点。12 秒探查收到 119 帧，首末接收时间计算 10.053 Hz，相邻接收间隔约 96.99–102.23 ms，header stamp 严格递增。端点为 reliable / volatile，报告的 history UNKNOWN、depth 0 不用于推断真实发布队列深度。

首帧为 `laser_frame`，449 个距离值及 449 个强度值；其中 437 个在配置量程内，6 个零值、6 个 NaN。保留首帧完整数组及所有帧的时间/数量统计。首次 `scan_time` 约 0.05209 s，不能等同约 0.1 s 的物理转一圈周期；沿用[接口审计](dogzilla-interface-audit-2026-11-05.md)的源码解释：header 为主机开始等待扫描的时间，非已验证的首束采样时刻。

驱动收到 SIGINT 后再次输出 `*** buffer overflow detected ***: terminated`，退出码 −6。最终容器已删除、UART1 释放；“资源已释放”不表示“驱动正常退出”。正式流程仍须先关闭并核验 bag，再退出驱动；该组合本轮尚未录包验证。

当前雷达二进制及 launch SHA-256 与 11 月 5 日记录一致。launch 中 `base_link → laser_frame` 的 z=0.18 m 是厂商配置，未做实机测量；本轮不把它作为已校准 TF 发布。其他 TF、相机内外参、IMU 安装关系仍须核实。

初始无 ROS 容器运行，本次隔离图仅启动雷达；没有获得现成 `/odom` 的证据。没有启动全套厂商控制栈，也没有以此次图中没有 `/odom` 推断硬件绝不提供里程计。已有里程计来源继续标记未确认。
