# 未修改上游与最小组件自研替换：工作量汇总

日期：2026-11-02。状态：三个 research 子代理的评估汇总；用户已确认采用最小组件替换策略及下述扩大范围前重新评估的边界。未选定具体重写对象、未构建或真机验证、未提交或发布 issue。

## 结论

用户已明确替换边界为“最小独立节点或组件，上游库保持原样”。按这个边界，策略适合本项目作为维护原则：可用原版库与算法保持独立，项目拥有自己的启动、配置、业务编排和必要的小适配节点。它主要减少私有补丁维护和更新合并成本，**不会消除接口兼容与集成验证，也不能保证比小补丁更省开发时间**。

已确认采用有条件的顺序：原版组件加项目配置即可满足时直接复用；公开接口可组合时外置适配；确有缺口时替换最小独立组件。若缺陷进入驱动协议或算法核心，先评估更换未修改的版本/组件或调整非必需功能，不自动升级为大型重写。

## 工作量

单位为人工投入小时，包括理解、agent 输出审查、实现、代表性验证和修正。各代理分别按模块拆项；C/D 的集成项只计 C/D 的参与人时，最小 CI 计入 D。以下是工程判断区间，非实际测量、概率区间或排期承诺。

| 范围 | 即使允许上游补丁也需完成 | 当前策略直接新增 | 策略下合计 |
| --- | ---: | ---: | ---: |
| A：设备、执行适配与首包 | 19–30 | 2–10 | 21–40 |
| B：运动估计接入、建图与保存 | 18–32 | 0–4 | 18–36 |
| C/D：保护、交互、启动、最小 CI 与其联调 | 30–52 | 0–6 | 30–58 |
| **总计** | **67–114** | **2–20** | **69–134** |

假设驱动和匹配控制库基本可用、已有成熟建图组件可启动、无需另研运动估计、C 的候选几何组件可原样接入、采用最小交互入口，且硬件及操作人员及时可用。估算未包含交付版定位、多地图与完整边界验证，也没有将等待时间算成人时。

原定四人两周每人至少 10 小时/周，约 80 人时只是最低投入参照。69–134 的范围跨过该参照，说明顺利路径有可能满足，但没有足够证据保证两周必达；在按 80 人时安排时余量偏紧。并行 agent 能缩短部分实现时间，不能替代现场验证或把人时直接换算为两周工期。

条件性风险不能机械叠加：C 若需自研小型几何保护组件，较原样候选路径可能另增 6–14 人时；B 换成熟算法可能增 8–20，另集成运动估计可能增 12–30 起；A 缺匹配库或驱动内部需修正会进入另一估算分支。它们并不全是“不改上游”的净成本，允许补丁的方案同样要诊断、实现与验证缺口。

## 按模块的可执行边界

| 模块 | 值得自研替换的最小单元 | 优先保留原样的部分 |
| --- | --- | --- |
| A | 执行适配节点、反馈发布节点、项目启动与 TF 组合 | 已验证可用的雷达驱动、串口库、底层步态与固件 |
| B | 项目 launch/参数、地图保存协调与结果反馈 | 可用的 SLAM、运动估计及地图工具 |
| C | 持续操作、故障确认、降级、踏步/停止等业务逻辑；必要时窄范围方向过滤组件 | 满足需求的几何计算或碰撞组件、ROS/TF 库 |
| D | 用户入口、流程协调、状态展示、项目 launch 与 CI 配置 | ROS 启动框架及各模块原版依赖 |

不修改上游仍需要检查版本、依赖、消息、QoS、单位、坐标系、时间戳、错误语义和资源占用。自研代码增加后，其格式、类型与测试责任也随之增加；对未修改依赖不强制套用本项目格式，本身即可减少无效改动，无需为此重写功能。将上游文件复制改名再改实现，不会消除其来源和后续维护责任。
