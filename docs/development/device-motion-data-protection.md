# C 模块如何使用阶段数据

编写于 2026-11-18。用于扫描解析、障碍判定和运动保护逻辑开发。离线只运行 C 的判断逻辑及模拟执行端。包内已有动作事件用于标记历史样本，C 的当前决策由测试输入产生。读取方法见[数据包与离线复现](device-motion-data-package.md)。

## 从扫描到保护结果

数据通路是 **A 的扫描与设备报告 → C 的判定**，控制通路是 **用户持续操作 → D → C → A**。C 评估所请求运动空间，向 A 输出受保护的指令，向 D 报告阻挡、限制或故障原因。实时判定所用的是雷达及与机身的坐标关系，可以独立于 B 的地图和全局定位开发。项目行为以[阶段决议 §7.2–§7.10、§7.26](../architecture/interface-baseline-decisions.md)为准。

| 要验证的判断 | 用什么数据 | 怎么判断完成 |
| --- | --- | --- |
| 每帧角度与距离解析 | 静止和最终动态 `/scan`，以及 `/tf_static` 的厂商外参 | 输出每帧有效点、无效点和所请求运动空间的覆盖情况。数组长度变化和角度边界测试通过 |
| 静态障碍的限制决策 | 用静止轮次做稳定性检查，用动态直行与转向窗口检查看到的局部空间变化 | 固定测试意图，逐帧输出通过、阻挡或空间未知及对应原因。带已知障碍位置与尺寸的标注样本或合成样本提供期望结果 |
| A 报告雷达故障到 C 响应 | 以零扫描诊断轮次的 probe/log 为案例。用离线注入重建“有端点但没有有效数据”、过期或恢复，并显式注入 A 的故障报告 | 输入、A 报告、C 运动限制和发给 D 的原因可追溯。动态主轮次用于正常数据基线 |
| 持续操作、阻挡解除和失联分支 | 使用模拟持续按键、松开、新操作、A/C/D 故障和模拟执行端。用原始 `events` 验证历史事件读取 | 模拟执行端只接受 C 输出，记录每次授权、限制、停止和恢复。超时责任与快速验证版的雷达降级路径分别覆盖 |

解析时用每帧的增量、长度及声明量程，并保留缺失、零值和非有限值对应的未知空间。所需空间无法确认时，输出相应原因；由 A/C 共同核实哪些情况构成雷达故障及对应报告。转向和踏步需要考虑实际机身扫过范围，外参和机身方向先与 A 核对。厂商角度重排与数据有效性的细节见 [A 的扫描证据](device-motion-data-device.md#扫描和静态-tf)。

## 保护状态机的回归用例

下列用例用于细化模块逻辑，按项目已定责任拆分测试。快速验证版由 A 集中检测和报告设备与数据错误，B/C 根据报告响应。C 仍负责 D→C 的有效操作指令超时，A 负责 C→A 的执行侧指令超时，D 负责用户操作端→D 的连接。

| 模拟输入 | 应核对的输出 |
| --- | --- |
| 有效持续操作，扫描确认对应方向被阻挡 | 停止被阻挡方向的移动。按共同基线，在链路仍有效且操作保持时进入原地踏步预期，松开后要求停止踏步。保持按键且新的有效结果确认可通行时，允许恢复 |
| 操作端失联、指令超时或保护链路重启 | 相应责任模块触发停止行为。恢复后要求松开再重新操作，C 对新意图重新检查 |
| 快速验证版中 A 确认雷达不可用并报告 | 立即停止平移和转向，原有持续操作下进入踏步预期并等待确认，松开时停止踏步。D 收集确认后交 C，确认本身不发运动。再次按住才允许降级运动，同时提示避障未生效 |
| 雷达降级过程中又发生通信或运动故障 | 执行相应更高故障响应，留存原因和优先级 |
| B 定位异常而 A 的扫描与运动链路健康 | C 的本地障碍判定继续使用有效感知与当前指令 |

这些期望的底层能力、保护范围及物理效果需经 A/C 实测。阶段样本中的 `STOP_WRITTEN` 描述宿主写入完成。最终动态轮次 `verification/session_evidence/deployment/checked_motion.py` 保存了中间轮次事故后增加的采集门禁，用来理解发出单次动作前怎样检查录制健康。正式 C 的保护策略按[阶段决议 §7.4–§7.10](../architecture/interface-baseline-decisions.md#74-已确认避障阻挡与其他中断分别处理)设计。

## 真机验证需要的参照

- **障碍与保护距离**由 A/C 先确定机身及踏步扫过范围、障碍相对位置、测量参考点、扫描覆盖和重复测量方法，再核对近距离、遮挡、转向等场景。真实样本的帧率、最大间隔和现场约值作为场景背景，保护距离和超时使用独立实测依据。
- **停车与失联**由 D 协调现场试验，分别记录保护触发、C 输出、A stop 写入、实际停止移动与停止踏步的时刻及位置。保留不同失联位置和恢复动作的记录，观察是否按预期停稳且只能经新操作恢复。强制断电能力由 A 核实，物理效果另验。
- **加速度异常检测**属于可延期项。动态 raw IMU 不可用于这一判定的实测验证。继续评估需同过程有效反馈、明确物理语义，以及对应正常和异常运动的参照。

交 D 的材料包括轮次/样本来源、保护输入和输出时间线、每个模拟分支的期望与实测结果、A/C 约定的故障接口，以及真机待验条件。对应工作见[模块研究事项](../architecture/interface-baseline-decisions.md#9-发布与记录状态)中的 #5、#8、#9。
