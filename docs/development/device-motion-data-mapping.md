# B 模块如何使用阶段数据

编写于 2026-11-18。用于运动估计、建图回归和单地图保存开发。先按[数据包与离线复现](device-motion-data-package.md)核对输入，零硬件依赖的播放组合见 [D 的回放配置](device-motion-data-integration.md#回放配置)。

## 用哪些输入

| 开发问题 | 数据及用法 | 结果解释 |
| --- | --- | --- |
| 扫描解析、静态显示、静止漂移 | 静止轮次的 `/scan` 和 `/tf_static`。核对 `laser_frame`、有效距离、静态 TF 和地图/位姿在等待期间的变化 | 可重复对比解析结果、静止噪声和算法输出漂移。物理精度仍需独立参照 |
| 扫描匹配、候选运动估计、建图 | 最终动态的整轮 `/scan` 与厂商静态 TF。用五个窗口查看三档直行和两次短转向，用等待段检查误运动和恢复 | 可检查有无输出、跳变、丢跟踪、重复结构及直线/转向处理差异。阶梯输入和现场约值仅辅助解释 |
| 反馈解析和缺失回归 | 静止 `Feedback` 核对协议与结构，动态 `Feedback.valid=false` 验证消费者拒绝原始 IMU/关节无效样本 | 静止反馈与动态扫描各自使用。融合评估需要同过程且有效、已核实单位和轴向的动态数据 |
| 地图持久化 | 将离线算法产出的地图或独立固定样本用作保存输入，验证 B 的保存结果与 D 的调用契约 | bag 是传感器输入。完整保存、失败保留旧地图、替换行为由 B 用实际地图产物及状态验证 |

包内只有 `base_link → laser_frame` 这一条 TF，缺少 `odom`、`map`、标准 IMU/关节和位姿真值。B 为算法选择并提供 `odom → base_link` 和 `map → odom`，A 确认传感器段，D 检查每段只有一个发布者。运行候选组件前先记录它需要的扫描帧、TF、运动估计与时间，明确每项依赖由哪一层提供。用恒等变换时，仅把它用于隔离的接线或显示测试，并标明占位。建图候选与角色说明见[共同基线](../architecture/interface-baseline-decisions.md#76-已确认tf-责任划分)与[建图复用评估](../report/upstream-policy-mapping.md)。

## 离线开发顺序

1. **打通静止输入。** 在隔离环境加载静态 TF、扫描和统一播放时钟。写出算法实际收到的帧数、frame、header 时序和 TF 查询结果。若接收或 TF 失败，先核查 QoS、TF 缓存和回放启动顺序。扫描时序的物理含义见 [A 的扫描证据](device-motion-data-device.md#扫描和静态-tf)。
2. **建立无融合基线。** 从二维扫描可支撑的运动估计/建图方案开始试验。候选如果依赖连续里程计，明确该轮能否由扫描单独提供相应估计，或将依赖标为待补。为同一轮固定算法版本、参数、起点、TF 和回放速率，输出轨迹、地图、缺 TF/拒绝帧、跟踪状态与每段变化。任何从控制输入推导的结果单列为假设或对比输入。
3. **比较五段及等待段。** 用 `motion_segments.json` 的精确窗口对齐报告。整轮回放用于比较连续估计，裁取窗口用于定位问题。保存算法在静止段的漂移、进入及离开动作窗口时的跟踪变化、有效点/跳变情况，以及地图中的重影或结构畸变。把采集观测、估计结果和外部参照各自标明来源。
4. **验证保存。** 从 B 启动建图及保存入口跑通处理中、成功、失败和原因。成功时核对所约定的完整产物可读取，失败注入后旧地图仍可用。由 D 读取 B 的公开结果，文件出现只用于产物核验。保存与后续定位、停靠位绑定的版本安排见[阶段决议 §7.12–§7.14](../architecture/interface-baseline-decisions.md#712-已确认bd-地图保存接口责任)。

## 下一次实验需要什么

- **继续选型**，用固定输入的运行日志比较能否接入、能否持续输出、何时丢跟踪、能否重复得到可读地图及计算开销。需要 Pi 5 测量的负载与耗时，由 D 组织目标环境验证。
- **评价运动估计和地图**，由 A/B 提出可测外参、室内已知几何、带时间和误差的位姿参照，以及包含足够平移、转向或闭环的轨迹。当前五段是功能样本，地图尺度误差、定位精度、漂移和闭环效果应以专门采集及量化参照验收。
- **评估融合**，明确需要的来源、最低有效频率、允许的间隔/延迟、单位、坐标系、标定与时序证据，再交 A 补同过程数据。动态反馈恢复后，保留禁用与启用融合的对照实验。

交 D 的最小结果包括轮次与 manifest、时间/TF 配置、候选版本及输入依赖、整轮与分段结果、地图保存验证记录，以及预计需要的补采。对应工作见[模块研究事项](../architecture/interface-baseline-decisions.md#9-发布与记录状态)中的 #6、#7。
