# 无相机动态阶段数据使用指南

编写于 2026-11-18，适用于 2026-11-11 的 `slam-stage-data-20261111.tar.gz`。现场操作、交付范围和异常经过见[动态采集报告](../report/device-motion-stage-capture-2026-11-11.md)与[无相机静止报告](../report/device-no-camera-stationary-capture-2026-11-11.md)。

## 从哪个轮次开始

- **调通扫描订阅或检查静止表现**时，从 `datasets/20261111T110119-67933b8eeecf/` 开始。约两分钟静止，包含 1,220 帧扫描和协议校验通过的原始反馈。
- **验证运动中的扫描处理**时，用 `datasets/20261111T162132-97e6f5fe7058/`。约九分钟连续录制，包含 5,647 帧扫描、三段直行、左右转及等待过程。用软件事件定位五段，保留段间上下文。
- **复现采集故障**时，按故障选择 `diagnostics/` 下的准备阶段零扫描或录包锁冲突轮次。先消费其日志和故障证据。目录与轮次 ID 见[数据包与离线复现](device-motion-data-package.md)。

动态轮次的原始 IMU 和关节反馈全部为 `valid=false`。静止和动态属于不同会话，分别作为测试输入。动态开发可用扫描、厂商静态 TF、软件动作事件和设备状态。物理速度、转角真值、停车效果、动态融合、地图精度和完整运动保护仍需独立验证。相机未参与本阶段采集，外部视频未随包交付。

## 数据经过哪些组件

这次真机上由 A 的临时采集入口写入带时限的动作并产生事件。厂商 MS200 驱动独立发布扫描，采集器在树莓派本地记录两个来源，封存后导出到电脑。整机运行的用户指令通路是 **用户 → D → C → A**。A 向 B/C 提供数据和设备错误，B 负责建图与地图保存，C 负责运动保护，D 协调流程并汇总结果。项目职责见[顶层架构](../../README.md#6-已确认的顶层架构与候选组件)。

## 按任务查阅

| 正在做什么 | 读哪篇 |
| --- | --- |
| 接收数据、找包内文件、核对话题、截取动作窗口、复现回放 | [数据包与离线复现](device-motion-data-package.md) |
| **A** 接入 MS200、核实反馈有效性和时间、交付运动与停止能力 | [设备接入与运动接口](device-motion-data-device.md) |

| **C** 解析扫描、验证障碍判定和持续操作逻辑、设计停车验收 | [遥控与运动保护](device-motion-data-protection.md) |
| **D** 配置隔离回放、汇总模块状态、组织闭环验收和补采 | [运行流程与集成验证](device-motion-data-integration.md) |

开始开发前，记录轮次 ID、所需数据与时段、验证通过的条件。结束时保存配置、输出和剩余缺口，以便 D 按相同输入复验，A 按需补采。
