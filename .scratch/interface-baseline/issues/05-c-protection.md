# C：细化持续操作、障碍限制与故障响应方案

## Question

在用户→D→C→A 通路中实现方案设计：默认无有效操作不运动；持续操作才持续运动，松开停止。障碍阻挡时保持按键可踏步，后续有效检测确认通行可继续移动；其他中断恢复需松开再操作。

快速验证版 A 报告设备错误、B/C 根据报告响应；雷达错误停止平移转向，在原有持续操作下踏步并等待 D 用户确认，C 管理确认和放行，确认后重新持续操作可运动并提示避障未生效。运动指令失联按层级 2 停止踏步；C 检测 D 有效操作指令超时。

产出：状态与接口提案、保护几何和参数证据、A/C 运动与停止测试方案、实际覆盖/延期范围。静态障碍场景；不引入自主导航。与 D 确认用户意图新鲜度，不能把旧操作续期。

## 共同约束

快速验证版先跑通人工操作、采集、建图、保存；交付版补定位、多地图与完整约定验证。用户→D→C→A；保持厂商硬件与底层步态，上游实现不修改，缺口按最小独立节点/组件自研替换。Ubuntu 22.04 / ROS2 Humble，默认 Python 3.10，按需 C++17。新增依赖自行查冲突，无冲突走 PR，有冲突提交 issue。

本 issue 是研究与方案细化的移交，不代表能力已经实现，也不要求在本轮完成代码。影响共同接口或故障规则的变化由相关模块与 D 确认。A/B/C/D 各自保留模块日志，试运行后交叉核对，D 协调。当前日期未定。
