# D：细化用户入口、状态反馈与试运行日志核对

## Question

D 接收全部用户指令并按能力归属请求 A/B/C；运动必须经 C，不绕过 C 直接要求 A 运动。D 检测操作端失联并通知 C，提供雷达故障确认入口，C 判断是否放行；保存结果以 B 回复为准。

仅 A→D 错误上报通道故障且其他必要链路正常时，快速验证版继续正常运行策略，不因此降级或停车，也不新增独立检测/冗余。通道故障不等于整体正常，已观察到的异常记录反馈；不能扩大为所有 A 通信异常都不处理。

产出：输入设备/界面方案、D/C 操作及确认契约、状态展示规则、各模块独立日志的最小共同字段与采集/事后交叉核对流程。字段和实现由模块细化，日志不替代实时停止。

## 共同约束

快速验证版先跑通人工操作、采集、建图、保存；交付版补定位、多地图与完整约定验证。用户→D→C→A；保持厂商硬件与底层步态，上游实现不修改，缺口按最小独立节点/组件自研替换。Ubuntu 22.04 / ROS2 Humble，默认 Python 3.10，按需 C++17。新增依赖自行查冲突，无冲突走 PR，有冲突提交 issue。

本 issue 是研究与方案细化的移交，不代表能力已经实现，也不要求在本轮完成代码。影响共同接口或故障规则的变化由相关模块与 D 确认。A/B/C/D 各自保留模块日志，试运行后交叉核对，D 协调。当前日期未定。
