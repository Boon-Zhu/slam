### Q15：人工逐段触发与本地计时结束（已确认）

用户确认采用人工逐段触发：操作者选择直行、左转或右转，设置指令幅度与持续时间，人工触发该段；机器人执行期间持续采集，由机器人本地计时，到时发送停止指令。操作者可提前手动发送停止，人工确认现场状态后才触发下一段，不自动连续执行整套动作。

该方式用于记录指令时段和重复实验，不依赖电脑通过 Wi-Fi 精确发送结束指令。持续时间限定指令执行时段，不保证实际位移、转角或精确物理停止时刻；属于动作流程，不增加避障功能。具体幅度与时长待实测确定，未在本轮执行动作。

本地计时与串口反馈阻塞的调度仍须验证；本地到时发送停止不等于已实现断联停车、进程失效停车或底层停止确认。跨动作的录制组织按 Q16 执行。

### Q16：连续录制与片段标记（已确认）

用户确认一轮采集中连续录制多个动作，不为每个动作重新启停录包。保留动作前后和等待期间的数据，用事件记录与指令时间标记定位各段；每次运动仍按 Q15 由人工单独触发。

参考组织：开始录制 → 静止 → 直行 → 停止/观察 → 左转 → 停止/观察 → 右转 → 停止/观察 → 结束录制。该示意不表示自动连续执行，也未确定各段时长或重复次数。

中途人工搬动机器人或改变设备配置时，记录该事件，并将之后的数据另分片段，避免误认为运动连续。连续录制与逻辑片段划分分别处理，不要求每个片段对应一个物理文件。

用户要求将可独立决定的语义问题合并在同一轮讨论。每轮列出当前前置条件已满足的问题；依赖未回答问题的后续问题留待下一轮。源码事实和实测参数由调查解决，不要求用户猜测。

### Q22：单独转向（已确认）

用户确认左/右转只下发转向指令，不叠加前进或横移指令。不假定实际运动完全绕固定点旋转，实际位移通过现场参照记录。

### Q23：直行三档速度、左右转各单档角度（用户修订后确认）

用户不要求相同动作、相同参数重复采集，改为执行时测量三个不同速度值，用于判定实际速度与移动函数输入数值之间的关系；不采用之前“同参数至少重复三次”的建议。质量不合格时按 Q12 补录，不与取消例行重复混淆。

用户进一步明确：只对实际使用中需要变速的直行测量三档速度；左、右转各测一个角度值，不做三档转向测量。按当前范围计划三段直行和左/右转各一段，共五个运动片段；质量不合格时仍按 Q12 补录。

执行方案应区分函数输入与实测速度，不能把未经校准的输入当成目标物理速度。每次转向需记录对应的输入和持续时间，单次测得角度不等于任意持续时间的固定转角。速度计时口径按 Q26；具体输入、持续时间及现场距离/转角测量布置仍待细化，不因只有三个测量点就默认全范围线性关系成立。

### Q24：控制与反馈读取的调度优先级（已确认）

用户确认停止和运动指令优先于启动下一次反馈读取，不为追求固定反馈频率拖延控制。反馈间隔变化时记录真实时间和间隔，不伪装成等频采样。

正在进行的串口读取可能阻塞，需设计和验证其最坏等待及控制时序；本原则不承诺能瞬时打断未修改的厂商库读取。

### Q25：正常结束顺序（澄清后已确认）

用户要求核实“结束动作”的含义。按已确认 Q15，动作由机器人端代码在本地计时到期或接收提前停止请求后调用停止接口结束，不要求电脑再发送一次常规结束指令。停止接口已调用与实际停稳分别记录。

用户确认正常录制收尾顺序为：最后一个动作由机内代码调用停止 → 人工核对实际停稳并保留末尾静止数据 → 关闭录包、检查文件 → 停止采集节点及驱动 → 释放设备。各动作之间保持录制，只有整轮采集结束才执行文件关闭与设备释放；厂商程序仍按 Q20 显式恢复，不自动重启。

### Q26：行进区间平均速度（已确认）

用户确认直行采用行进区间平均速度：地面设置两条已知间距的标记，以机身同一参考点经过两条标记的时间差计算速度；起步和停止安排在测量区间之外。

可以使用外部视频自身时间测量，无需与机内数据对齐。三个档位采用同一测量口径，记录距离、通过时间、参考点、计算结果和误差。若场地不足以提供该区间，应明确改用整段平均速度，不混用两种结果、不静默更改口径。区间平均值不自动证明速度已达稳态，也不代表瞬时速度真值。

7. 最后一段由机内代码停止，人工核对停稳并保留末尾静止数据；关闭录包、检查文件，再退出驱动、释放资源，不自动重启厂商 APP/OLED。异常恢复按 Q21，不自动续动作。

校时、部署、存储不可写等使录制本身无法成立的问题，不能通过“接受来源缺失”绕过。本项细化开始录制的操作选择，不改变 Q3–Q5 的缺失项交付及补采责任；就绪与有效性的具体技术判据待实现验证，不要求用户猜测技术事实。

#### Q35：确认录包失败后尝试停止当前动作（已确认）

确认 recorder 异常退出或写盘失败时，采集工具调用已有 `stop`，尝试提前结束当前动作，报告本轮录制失败并保存残留文件和日志。不自动重启录包或续动作。

这是在 Q15 本地计时和手动停止之外新增的录制故障响应，不增加避障功能，不把普通 SSH 断线当作录制失败，也不代表完整 C 模块运动保护已实现。停止请求结果与实际停稳分别记录；实际停稳仍由现场人员观察。若停止链路也已失效，须保留失败或未知结果，不能宣称已停止。

### 第 4/6 轮

#### Q36：单来源中断时保留其余录制（已确认）

录制过程中某个来源停止出数据，但 recorder 和其他来源仍正常时，继续保存其余来源，报告缺失来源及受影响区间，由操作者决定何时结束。不因此自动停止当前动作，不自动重启故障驱动；当前动作仍按原期限结束，操作者可提前停止。

单次无效反馈不直接等于来源中断，检测依据需结合来源实际频率确定。整体 recorder 退出或写盘失败仍按 Q35 处理；异常对交付的影响和补录按 Q12 判断。

#### Q37：显式正常结束及资源收尾（已确认）

操作者先观察实际停稳并保留所需末尾静止数据，再显式执行结束命令，不额外增加“确认停稳”的现场标记步骤。入口 READY 不代替人工停稳观察。

结束命令关闭 recorder、检查文件、停止采集节点和驱动、核对资源释放并保存日志。入口仍有待执行或正在执行的动作时，拒绝正常结束并提示先停止。文件检查失败仍保留证据并完成资源收尾，但结果报告为异常，不显示“正常完成”；APP/OLED 不自动恢复。

#### Q38：每次录制后独立导出（用户修订后确认，细化见 Q39/Q40）

用户说明“这三轮会分三次录制，每次录制之后单独导出数据”，同意分配唯一 ID，但不要求生成不可覆盖的目录；用户将此与当前仅维护一份地图的规划联系起来。

本题确认每次录制后独立导出及唯一 ID 的方向，不把“不要求不可覆盖目录”解释为允许删除或覆盖未导出数据。后续 Q39 已明确机器人端原件保留规则的修订以及录制位置复用条件。

“单地图”针对地图产物，原始录包属于另一存储对象，依据阶段决议 §7.15 和 GLOSSARY 的当前地图定义，不由单地图约束推导录包覆盖规则。后续 Q40 已澄清轮数，维持 Q19 先静止验证、再连续运动的两轮安排，补录按需发生。

### 第 5/6 轮

#### Q39：校验导出后显式清理并复用录制位置（已确认，修订 Q17）

机器人使用固定的当前录制位置，每次结束后导出到电脑，电脑按唯一 ID 保留各轮完整数据。导出并核对完整性后，操作者显式清理机器人端这一轮，再开始下一轮；不要求机器人为每轮生成不可覆盖的独立目录。

未导出、校验失败或清理尚未明确执行时，拒绝覆盖已有数据。异常轮次也先保留并导出证据。本项修订 Q17 的机器人端原件持续保留要求，不授权自动清理，也不授权当前讨论期间执行删除操作。Q21 的新轮次身份及不伪装连续性仍有效；物理位置可在满足上述导出、校验及显式清理条件后复用。

#### Q40：静止与运动两轮，按需补录（已确认）

必做静止录制和连续运动录制两轮，补录只在数据质量不合格等实际需要时增加，不新增固定第三轮。三档直行及左右转仍放在同一轮连续运动录制中，各动作人工单独触发。

#### Q41：每轮自动校时与部署准入（用户修订后确认）

用户明确校时是每次录制前都要执行的步骤，要求直接安排在自动化脚本中，修订 Q27 对校时执行责任的安排。每轮自动校时与入口/驱动启动的先后关系、失败处理按后续确认的 Q43 执行；具体技术路径及对时精度仍须调查验证，不凭空规定阈值。

部署门禁按建议确认：核对实际运行的代码、配置、镜像及依赖版本，确认入口 READY、真实后端、预期运动开关和有效固件响应；雷达、相机另查实际出数。不只看进程是否存在。具体命令和核查方式需实现验证，已有只读探查脚本不直接充当完整门禁。

#### Q42：机器人文件检查、电脑完整性与回放验证（已确认）

机器人完成关闭后的文件可读性、消息数量及覆盖检查；电脑对导出副本完成哈希核对和实际 ROS 回放。每轮独立导出并检查，首个静止轮次通过后才进入运动录制。

导出内容包含 bag、日志、配置、来源及异常说明，并提供自定义消息的对应版本与构建/回放说明，便于其他成员独立使用。外部视频、测量结果和片段关联仍按 Q30/Q32 整理。不把导出成功、哈希一致、回放检查通过或全量覆盖核实完成混为同一状态。

### 第 6/6 轮

#### Q43：每轮准备时自动校时，再启动设备节点（已确认）

每轮准备命令按以下顺序执行：自动校时并验证结果 → 核对部署和资源 → 启动控制入口、雷达及相机 → 检查来源 → 等待电脑显式发送开始录制指令。

校时失败则准备失败，不能开始录制。已有录制正在进行时，重复准备请求被拒绝，不中途改时或重启设备。校时发生在本轮设备节点启动之前；准备和开始录制仍是两个明确操作。具体时间源、命令和偏差测量方式由环境调查确定，并保存实际校时证据。

#### Q44：两轮独立执行，显式指定运动模式（用户修订后确认）

静止验证与运动录制分为独立两轮执行，运动准备不读取静止验证报告，也不要求工具通过报告关联来自动放行运动。操作者显式指定运动模式；未指定运动模式时沿用入口默认禁止运动的行为。准备或开始录制本身不下发动作，各动作仍由人工通过既有入口单独触发。

不采用此前“运动准备读取静止检查报告并匹配轮次、来源和录制配置”的建议。Q19/Q42 中先完成静止录制及验证、再进入运动录制的操作顺序保持有效，由操作者按清单落实，不设置跨轮报告门禁。数据检查结果仍按 Q42 随对应轮次交付，不因不设门禁而免除实际文件、完整性与回放检查。
