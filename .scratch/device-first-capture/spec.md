### Q6：采集场景与外部影像（2026-11-08）

因设备争用或后续补采而分次记录时，明确标记为不同片段，不能拼成同一次运动的多传感器数据。关联与时间要求按 Q9 执行，外部影像关联不表示时间对齐。

### Q9：机内时间与指令时段（2026-11-08）

用户修订并确认：

- 采集前统一机内时间基准。
- 记录直行、左转、右转、停止指令的时间，作为动作时段标记。
- 各路机内动态数据对齐到该时间基准；无法直接对齐时，说明时间戳来源、含义及关联方法。

说明书区分指令时段与实际运动过程：指令发出不证明机器人已实际开始或停止运动，指令时间不作为实际动作发生的精确时间。运动指令用于时段标记，不能替代传感器时间基准的核实。

不采用上一版提议中“外部视频必须具有共同事件对齐依据”的要求。具体机内校时方法、时间戳关联方法和可达到的精度仍需后续核实，不在此承诺精确采样同步。

### Q15：人工逐段触发与本地计时结束（已确认）

用户确认采用人工逐段触发：操作者选择直行、左转或右转，设置指令幅度与持续时间，人工触发该段；机器人执行期间持续采集，由机器人本地计时，到时发送停止指令。操作者可提前手动发送停止，人工确认现场状态后才触发下一段，不自动连续执行整套动作。

该方式用于记录指令时段和重复实验，不依赖电脑通过 Wi-Fi 精确发送结束指令。持续时间限定指令执行时段，不保证实际位移、转角或精确物理停止时刻；属于动作流程，不增加避障功能。具体幅度与时长待实测确定，未在本轮执行动作。

本地计时与串口反馈阻塞的调度仍须验证；本地到时发送停止不等于已实现断联停车、进程失效停车或底层停止确认。跨动作的录制组织按 Q16 执行。

### Q16：连续录制与片段标记（已确认）

用户确认一轮采集中连续录制多个动作，不为每个动作重新启停录包。保留动作前后和等待期间的数据，用事件记录与指令时间标记定位各段；每次运动仍按 Q15 由人工单独触发。

参考组织：开始录制 → 静止 → 直行 → 停止/观察 → 左转 → 停止/观察 → 右转 → 停止/观察 → 结束录制。该示意不表示自动连续执行，也未确定各段时长或重复次数。

中途人工搬动机器人或改变设备配置时，记录该事件，并将之后的数据另分片段，避免误认为运动连续。连续录制与逻辑片段划分分别处理，不要求每个片段对应一个物理文件。

### Q17：无线操作、本地录制与采集前扩容（已确认）

用户确认：电脑经 Wi-Fi SSH 操作机器人端控制入口；控制、反馈采集与 ROS 录包运行在机器人端，ROS 通信先限定在机内。数据写入机器人宿主持久目录，经挂载供容器访问；录制结束并检查文件后经 Wi-Fi 复制至电脑，核对完整性，仍保留机器人端原件，不自动删除。

不以跨机 DDS 或 Wi-Fi 持续传输全部传感数据作为先决条件。磁盘容量、写入负载及可录制时长仍须验证。

用户追加要求：开始采集前扩容机器狗搭载的磁盘。扩容完成并验证作为采集前置条件；本轮仅确定顺序，未执行分区或文件系统变更。

已有 2026-11-05 系统报告记录：设备 /dev/mmcblk0 为 58.240 GiB、根分区 30 GiB、卡尾约 27.736 GiB 未分配。执行准备优先核查能否利用现有卡尾空间扩展根分区及 ext4，保留厂商系统与数据；这是历史布局，须先复核当前设备、备份与恢复条件，再制定具体操作。不将新增容量当成已可用，不因扩容要求自行删除镜像或其他数据。

### Q18：静态试采与静止片段合并（已确认）

用户明确静态试采可与观察数据基线、噪声和时间连续性的静止片段采集合并。因此首个静止片段兼作采集流程验证，通过相应检查后直接纳入数据集，不另行重复采集一份同用途试采数据；异常数据按 Q12 保留并判断补录。

### Q19：先验证静止录包，再开启运动录制（已确认）

用户确认按两轮组织：

1. 静止录制兼作试采，采集基线、噪声和时间连续性；关闭录包后完成持久化、文件读取/回放及无线取回检查。

用户确认左/右转只下发转向指令，不叠加前进或横移指令。不假定实际运动完全绕固定点旋转，实际位移通过现场参照记录。

### Q23：直行三档速度、左右转各单档角度（用户修订后确认）

用户不要求相同动作、相同参数重复采集，改为执行时测量三个不同速度值，用于判定实际速度与移动函数输入数值之间的关系；不采用之前“同参数至少重复三次”的建议。质量不合格时按 Q12 补录，不与取消例行重复混淆。

用户进一步明确：只对实际使用中需要变速的直行测量三档速度；左、右转各测一个角度值，不做三档转向测量。按当前范围计划三段直行和左/右转各一段，共五个运动片段；质量不合格时仍按 Q12 补录。

执行方案应区分函数输入与实测速度，不能把未经校准的输入当成目标物理速度。每次转向需记录对应的输入和持续时间，单次测得角度不等于任意持续时间的固定转角。速度计时口径按 Q26；具体输入、持续时间及现场距离/转角测量布置仍待细化，不因只有三个测量点就默认全范围线性关系成立。

### Q24：控制与反馈读取的调度优先级（已确认）

用户确认停止和运动指令优先于启动下一次反馈读取，不为追求固定反馈频率拖延控制。反馈间隔变化时记录真实时间和间隔，不伪装成等频采样。

正在进行的串口读取可能阻塞，需设计和验证其最坏等待及控制时序；本原则不承诺能瞬时打断未修改的厂商库读取。

### Q25：正常结束顺序（澄清后已确认）

用户要求核实“结束动作”的含义。按已确认 Q15，动作由机器人端代码在本地计时到期或接收提前停止请求后调用停止接口结束，不要求电脑再发送一次常规结束指令。停止接口已调用与实际停稳分别记录。

用户确认正常录制收尾顺序为：最后一个动作由机内代码调用停止 → 人工核对实际停稳并保留末尾静止数据 → 关闭录包、检查文件 → 停止采集节点及驱动 → 释放设备。各动作之间保持录制，只有整轮采集结束才执行文件关闭与设备释放；厂商程序仍按 Q20 显式恢复，不自动重启。

### Q26：行进区间平均速度（已确认）

用户确认直行采用行进区间平均速度：地面设置两条已知间距的标记，以机身同一参考点经过两条标记的时间差计算速度；起步和停止安排在测量区间之外。

可以使用外部视频自身时间测量，无需与机内数据对齐。三个档位采用同一测量口径，记录距离、通过时间、参考点、计算结果和误差。若场地不足以提供该区间，应明确改用整段平均速度，不混用两种结果、不静默更改口径。区间平均值不自动证明速度已达稳态，也不代表瞬时速度真值。

## 执行方案汇总（已整体确认）

1. 采集前复核机器人磁盘布局、准备备份，完成扩容及容量验证；准备最小自研 ROS 统一控制/反馈入口，复用未修改厂商库。
2. 经 Wi-Fi SSH 操作；临时停用 APP/OLED 等实际占用者并核实设备释放。统一入口独占控制串口，雷达与摄像头独立采集；机器人宿主持久存储数据。
3. 首个静止片段兼作试采，关闭录包后验证文件、回放与无线取回，并测量存储增长和负载；该片段直接纳入数据集。
4. 验证通过后开启连续运动录制，人工逐段触发三档直行及左/右转各一段。机器人本地计时调用停止，可提前手动停止，不自动触发下一段。
5. 直行按 Q26 测行进区间平均速度，左右转记录各自输入、持续时间及实测角度；团队拍摄场地和运动，影像关联片段但不要求与机内时间对齐。
6. 机内统一时间基准，保留原始数据、指令时段、异常和未知项；控制优先于启动下一次反馈读取，实际阻塞与停止时序须验证。
7. 最后一段由机内代码停止，人工核对停稳并保留末尾静止数据；关闭录包、检查文件，再退出驱动、释放资源，不自动重启厂商 APP/OLED。异常恢复按 Q21，不自动续动作。
8. 交付数据、说明书及缺失清单，由 A/B/C/D 按 Q13 核对；随后安排制造商核实与必要补采，全量核实完成后才能关闭 issue #4。
