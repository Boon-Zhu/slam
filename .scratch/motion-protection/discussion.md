# Issue #8：面向 M1 的运动保护讨论

Status: needs-info

创建日期：2026-11-11。对应 [issue #8](https://github.com/Boon-Zhu/slam/issues/8)。本文件是本地讨论记录，尚未同步 GitHub，不代表完整 spec、实现授权或真机验收。

## 目标与讨论顺序

以 [README §8.2](../../README.md#82-三个集成里程碑) 的 M1 为目标，细化 C 的交付及与 A/D 的接口；B 的算法选择留在其对应 issue。

1. M1 中 C 的最小交付与延期范围。
2. 首批数据消费、质量限制与补采需求。
3. D→C 持续操作、新鲜度与状态反馈。
4. C→A 运动、停止、踏步与执行结果契约。
5. 障碍保护、故障响应及恢复。
6. 联调场景、参数证据和完成依据。

## 已确认

- 障碍进入合理的安全距离后，必须禁止继续向障碍前进，操作者不能通过持续按前进绕过限制；具体距离尚未确定。
- 障碍阻挡时，踏步是对仍有效的持续行进意图的反馈性动作；用户松开、请求停止或操作失效后，踏步也须终止。不是只要障碍存在就一直踏步。
- 此语义沿用[阶段决议 §7.3–§7.4](../../docs/architecture/interface-baseline-decisions.md#73-已确认默认不运动与中断后重新授权)；遇到要求停止行为的故障时，不得以障碍反馈为由继续踏步。
- 若采用自动退行或方向修正，它们也必须以有效持续平移操作为前提；对应操作松开或失效后，停止该平移、退行及其反馈踏步。当前不存在任何有效运动操作时要求停止全部运动；另有有效请求时按已确认的平移优先及切换等待规则处理。不增加无持续操作也能主动避让的例外，故障后的重授权规则保持有效。
- 用户要求候选保护方案保留一段距离区间：区间内既不继续靠近障碍，也不触发退行，用于容纳实机误差、延误与波动。具体边界、宽度及是否另需状态切换滞回尚未确定。
- 正常接近静态障碍时，预期先通过踏步或其他避免靠近的方式保持安全距离，因此不会触发退行。这是设计预期，不是停止距离、误差裕量或实际动态响应已经验证的结论。
- 用户确认“静态障碍通常无需退行”不是绝对禁止：候选方案不依赖判断或预测障碍的运动，统一按观测到的距离及通行条件响应。初始位置过近等情况也适用同一规则，不额外设计静态障碍或特殊起始过程分支；仍须满足有效持续操作、低速及退行方向可通行等已确认约束。
- 踏步语义已经澄清，但底层能力、实际位移与机身扫过范围仍待核实；不因业务定义成立就认定真机可安全执行。
- 若采用方向修正，只去掉用户请求中朝向障碍的移动分量，保留可通行的切向分量，不自行转向或选择侧向绕行。切向分速度很小时可以直接踏步；“很小”的判定口径与阈值尚未确定。这里约束的是保护自动生成的调整，不据此删除用户主动转向功能。
- 用户确认方向修正后的切向分量不自动放大，不补偿被削减的速度，也不为维持行走而抬高到最低行走速度；过小时可踏步。距离限速作为速度上限，不主动提高用户请求的速度。自动退行速度另行确定。
- Q8 澄清候选算法：以探测到的最小距离处确定远离障碍的方向，自动退行速度完全沿该法向；将其与用户请求运动的切向分速度叠加。未采纳助手提出的“沿用户请求方向反向退行”。此处的退行可以产生侧向平移，不意味着主动改变机身朝向或规划绕行路径。
- Q9 用户同意对最终合成速度检查其他障碍，并明确关注范围为用户请求方向与候选运动方向分别朝向的两个 180° 区域的并集。用户及时将最初的“交集”更正为“并集”；不继续按交集设计。坐标参考定义仍待明确。
- 用户确认最终检查时统一缩放整个合成速度：随障碍距离靠近而逐步降低速度上限，到安全距离停止；切向与退行法向分量同乘 alpha，保持非零合成速度的方向。
- 用户补充：含自动退行的运行还要乘附加系数 beta，取请求速率除以“退行最大速度与切向最大速度的合速度大小”，使合成输出指令速率不超过请求速率。该约束不等于实物速度及跟随误差已验证。
- Q11 用户确认切向上界固定取请求速率 R，采用 `beta = R / sqrt(U_max^2 + R^2)` 的保守缩放；即使当前合成速率未超过 R，也应用该系数，而不是仅在当前合成速率超限时截断。只要切向与退行分量正交、分别不超过 R 与 U_max 且 alpha 在 [0, 1] 内，输出指令速率不超过 R，任一分量也不会被放大。
- 用户确认固定使用“候选运动方向”，不是实测机身速度方向。Q32 进一步明确候选运动是 C 发送给 A、同时反馈给 D 的同一份指令数据；保护计算中的中间向量不构成另一套用户反馈。误差、响应延迟和停止过程仍需独立考虑，不能认为指令改变时机身立即改变运动方向。
- Q13 用户确认圆形包络的定义覆盖本阶段全部允许动作；实践可优先通过容易获取的踏步等测量估计半径，在安全距离充足的前提下接受其他动作与踏步之间的范围差异，必要时增加额外安全余量。该工程近似与已验证全动作最大范围分别记录，具体半径及余量数值尚未取得。
- 用户同意转向期间雷达基点位移需要后续测量并纳入考虑，不能仅依赖固定圆心的机身包络。
- Q14 用户确认纯原地转向采用 360° 全周净空检查，结合转向包络与余量判断是否允许转动；不套用纯平移的两个半平面并集。雷达已有全周扫描，改变的是消费与筛选范围，不需要为转向切换扫描模式。平移仍沿用 Q9 已确认的并集规则。
- Q15 用户确认平移与转向分别授权：任何平移（含方向修正、自动退行）仅在有有效平移请求时允许，任何转向仅在有有效转向请求时允许。纯转向受阻不会自动平移腾挪，纯平移请求也不会授权自动转向。请求中止或失效时对应运动终止；踏步仍遵循有效持续操作受阻时的反馈语义。
- M1 平移与转向互斥，只支持纯平移或纯转向；斜向平移仍属于纯平移。用户与其他开发者讨论后明确废弃 Q16 的后发覆盖，改为平移优先：存在有效平移请求时忽略转向请求；不存在平移请求时考虑当前有效转向请求；两者均无则停止。平移受保护限制后输出为零，不等于平移请求消失，不能因此转而执行转向。
- Q17 的先停后启规则保留，转向接入/退出并与平移切换时，先停止旧运动，再等待后启动新运动，以降低延迟造成的机械运动重叠风险。Q18 的计时起点及失败处理继续适用；等待时长尚未确定，定时等待不等同于实时物理停稳反馈。当前无有效请求时保持停止。
- Q18 用户确认切换等待从 C 收到 A 的“停止命令写入完成”回执后开始，而非从新请求到达或停止请求发出时开始；等待结束重新检查当前请求有效性与保护条件。停止失败或结果未知时，不得仅凭计时到期启动新运动。回执仍只证明软件写入结果，不是物理停稳反馈。
- Q20 用户确认停顿仅在向运动系统输出时发生运动类型变更的情况下触发，不由输入按键变化或请求周期刷新触发。平移持续优先时，被忽略的转向请求接入/退出不打断平移；同一输出类型的刷新不重复触发停顿或重置等待。
- Q21 用户将切换等待明确为停顿期：平移指令结束后的一段时间内，所有转向请求均不执行；转向指令结束后亦禁止平移。这个约束只限制另一类型的启动，不额外禁止同类型请求；平移优先、运动互斥、持续操作及保护检查仍有效。继续沿用 Q18：由 C 收到 A 的停止写入完成回执后开始计时，回执失败或未知不能启动另一类型。
- 若同类型运动在停顿期内重新启动，之后再结束，应以这次停止对应的回执重新确定对另一类型的停顿期；不能用上一次停止的已流逝时间放行尚未停下的新运动。这是按“每次运动结束后设停顿期”的规则推导，不需要保存历史动作队列。
- Q22 用户不采用转向渐变限速，选择二值保护：转向包络及所需余量范围内没有障碍时，按有效转向请求正常转向；有障碍时禁止转向，必要时提示用户。继续遵循平移优先、持续操作、全周检查及停顿期；受阻时的踏步和松开停止语义不变。
- 转向二值保护的几何前提：用于检查的圆应保守覆盖转向过程的机械扫掠范围。仅以当前雷达基点为圆心的机身包络不自动覆盖圆心移动，前面已确认需将其测量后纳入考虑；转向包络/附加余量的最终数值仍待确定。圆外障碍不进入机械扫掠范围是此前提下的几何判断，不是当前真机验证结果。
- Q23 用户确认转向采用不同的禁止与恢复距离阈值：进入禁止边界就停止转向，障碍需进一步远离至恢复边界后才允许恢复，以减少边界测距波动造成的反复启停。角速度仍采用二值保护，不引入渐变限速；恢复仍要求当前转向请求有效、平移优先规则允许且其他保护条件满足。阈值差的数值尚未确定。
- Q24 用户确认少量、分散的离散测距点缺失或无效可以忽略；连续或频繁无效点视为雷达故障，进入级别 1。少量、分散、连续和频繁的具体定义须结合数据分析，可能需要实测，当前不设数值。忽略容许缺失不等于把无效值转换为已确认的无限远空间。
- Q24 的故障判定沿用共同基线职责：A 检测并报告设备/数据错误，C 按级别 1 的雷达故障规则响应，D 提供状态和用户确认入口。快速验证版停止平移与转向，在原有有效持续操作下可踏步，松开则停止；确认前不接受新运动操作，用户确认后重新持续操作才可降级运动，并持续提示雷达不可用、避障未生效。确认不解除通信或运动故障限制。
- Q25 用户确认故障检测与避障是分开的功能模块，雷达数据有效性属于故障检测，检查全周数据，不随当前运动方向缩小范围。避障再依据有效数据，按平移检查区域或转向全周范围判断障碍限制。沿用 A 检测报告雷达设备/数据错误、C 响应的责任划分；功能分离尚不决定 ROS 节点、包或进程如何部署，通信失联检测仍按 D/C/A 接收端分工。
- Q26 用户确认 C→A 的正式运动接口采用经核实的机身坐标系物理速度：平移速度为 m/s，转向角速度为 rad/s。C 输出保护后的速度请求，A 负责映射为厂商控制输入及执行能力限制；需要实测建立映射，请求速度不能作为实际速度反馈，也不能将现有厂商幅度直接改标物理单位。
- Q27 用户确认 D 周期性一起发送完整的当前输入状态，包括平移请求、转向请求及有效状态，不提前按优先级丢弃转向请求；C 统一处理平移优先、停顿期、避障和故障限制，再向 A 输出互斥的一种运动。同一状态刷新只维持有效性，不创建独立动作；平移请求消失后，C 可依据当时仍有效的转向请求进入切换流程。输入失效/故障恢复仍受既定停止和重授权规则约束。
- Q28/Q32 用户明确 C 给 D 的反馈就是候选运动，与 C 给 A 的运动指令是同一份数据，不另设不同处理阶段的运动反馈。不要求 C 取得或反馈实际机械运动情况；不采用助手提出的“逐次向用户提示无法按请求运动的原因”，日常运动限制规则预期写入说明书。既有架构中 A 提供可用原始反馈/执行状态，B 负责运动估计，C 不因此新增物理运动估计职责。
- Q29 用户确认避障导致运动与请求不一致属于正常功能，雷达级别 1 属于故障异常，两者不采用相同处理；故障仍保留相应用户确认，不因取消日常避障原因提示而删除故障确认流程。
- Q30 用户确认冷却期同时是降级操作许可的有效期：从用户确认生效开始计时，期内不重复请求确认，允许按持续操作规则降级运行；到期时雷达故障仍在则停止平移与转向，再次请求确认。确认不自动生成运动请求，也不解除其他故障限制。具体时长尚待确定。
- Q31 用户确认有效期只看最近一次有效确认：雷达恢复或同类故障再次出现，不撤销尚未到期的许可，也不重置或延长计时；有效期内仍认可用户已接受雷达失效风险。只有新的有效用户确认更新起算时刻。该许可不覆盖通信/运动等其他类别故障，不自动恢复旧运动，持续操作及既定重新操作规则仍有效。

## 候选与未决

- 保护包络圆定义及优先用踏步估计的方法已在 Q13 确认；具体半径、动作范围差异的估计与额外余量仍待测量和记录。对可见障碍，`range - radius` 为到包络的保守净空；响应延迟、停止距离和雷达基点位移另行纳入保护边界。
- 转向扫掠的计算提示（助手推导）：若以开始时的雷达位置为固定参考，整个过程的包络半径可保守取 `R_body + max_t ||L(t)-L(0)||`；这里是全过程最大中心偏移，而不是转满 360° 后的起终点净位移。不能在未定义测量参考的情况下，把任意“位移”直接加到直径上。实际测量方法及是否采用此保守估计尚待细化。
- 额外几何安全余量与此前“既不靠近也不退行”的距离区间承担不同用途，参数组织及是否合并计入阈值尚待细化。
- M1 已改为平移优先，按 Q21 的停顿期对另一类型启动作时间隔离；此前停止后已经度过的时间可计入，不重复等待完整周期。同类型刷新不重置计时，真正重新启动并再次结束则产生新的停顿期。停顿时长及验证依据、停止失败后的恢复仍待讨论；日常限制原因不要求逐次向用户提示，按 Q28 写入说明书。
- 转向已确认不做渐变限速，并采用恢复边界比禁止边界更远的双阈值；包络及余量、双阈值数值及具体提示内容尚待细化。雷达缺失已确认按 Q24 区分容许的少量分散缺失与级别 1 故障，指标及阈值仍待数据分析和实测。
- 连续/频繁无效点故障判定已明确检查全周数据；具体空间/时间统计指标、窗口、阈值、恢复条件及 A/C 数据状态接口尚待确定，不把当前 97.6264% 有效率当成合格阈值。故障检测与避障的逻辑组件布局仍待细化，不能把职责分离自动解释为新增顶层模块或必须拆出独立 ROS 包。
- Q19 的“正常覆盖后必须松开重按”提案未被采纳；后发覆盖已被用户明确废弃，不再需要围绕它设计正常输入的历史请求恢复机制。故障恢复后的重授权要求仍按共同基线执行。
- D→C 已明确完整当前输入状态由 D 周期发送，类型选择与运动限制由 C 统一处理；具体消息结构、请求速度的表达、新鲜度/顺序/会话语义及周期仍待确定。D→C 的消息刷新不得将失效的用户操作续期；不因接口职责确认就视为已实现。
- C→D 与 C→A 使用同一份候选运动指令数据，反馈口径已明确，不再作为待讨论问题；具体消息字段仍待接口细化，不能把指令或软件写入结果显示成已确认的实际机械运动。故障确认许可按最近有效确认计时，具体时长、确认消息的有效性及会话边界仍待确定。模块日志要求未被取消。
- 用户提出 `range=0` 的待实机验证假设：比较从保护包络边界到雷达最小距离在若干帧内所需的接近速度；若该速度足够大，考虑将 0 按超量程、无近障碍处理。该假设尚未采纳为运行规则，当前不能据此把全部 0 从无效/故障统计中排除。
- 对上述假设的分析（待继续核实）：速度约束只能支持具有可信前序观测的连续接近过程，不能单独排除启动时物体已近于最小距离、驱动归零/桶处理等来源。包络半径、实际盲区、观测间隔和处理延迟、适用的相对速度上界以及启动前提均须明确；大跨越速度本身不证明所有零值都是超量程。
- 用户提供的现场尺寸与判断：上层外壳短边约 5 cm；以测量基点居中等几何前提估算，无接触可测距离可能约为 2.5 cm。用户认为在大多数方向，障碍距雷达 5 cm 时已可能触碰较宽下层或脚部，因此低于 5 cm 被过滤时可能已发生接触，视为届时无法再避免的接触情形。该尺寸为用户描述，尚无本轮测量记录；不能扩展为所有方向/高度的包络或雷达探测保证，也不等于所有零值可安全放行。保护是否已在更早有效测距阶段介入，需在动态验证中检查。
- C→A 已确定物理速度语义；具体参考点/坐标轴核实、消息形式、可执行速度范围与分辨率、低速能力、映射标定、能力不满足时的反馈及停止/踏步表达仍待细化。临时采集入口当前仍为厂商幅度与定时动作，不因接口方向确认就成为正式持续控制接口。
- 用户提出按障碍距离渐变限制最大前进速度，到安全距离完全禁止前进；更完整的候选包含退行，简化候选可依次去掉退行、速度渐变。用户要求结合可靠性、复杂度等比较，暂不选定方案。
- 用户澄清：退行候选由系统自动发起，采用缓慢速度，一般只在行进方向的障碍距离明显不安全、且退行方向可通行时执行。此处确认的是候选方案的含义，不代表已选入 M1。
- 用户补充：机器已经停止继续靠近障碍时可以不退行；斜向靠近时，可以修正行进方向，使机器不再靠近障碍。方向修正范围已在 Q6 澄清；具体触发条件、“靠近”的判定依据及切向速度阈值待讨论。
- 退行采用最近障碍确定的远离方向，但几何参考点、最近测点径向与真实表面法向的关系、没有可行退路时的处理仍待明确。多障碍检查范围已在 Q9 澄清为两个半平面的并集；退行速度上限及距离限速函数仍未确定。
- 已确认的候选公式为 `v_out = alpha * beta * (v_t + v_ret)`，其中 `beta = R / sqrt(U_max^2 + R^2)`。公式仅用于有效持续操作且含退行的分支，松开、请求速率为零或授权失效时直接停止，不依靠比例公式延续动作；实际采用何档方案及其 M1 范围仍待比较。
- 运动响应滞后、停止过程及跟随误差如何进入保护距离和检查范围，尚待细化；候选运动方向不是这些实物行为的证明，现有数据不能证明可获得可靠的实时实际速度反馈。
- 用户提出可为节约算力仅检查几个更可能靠近的方向，作为待评估优化；具体筛选方法、窄障碍覆盖及计算负载均未验证，尚未确定采样策略。
